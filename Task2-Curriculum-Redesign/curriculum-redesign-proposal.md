# Task 2 - 2030 CSE Curriculum Redesign

## 1. Executive Summary

This proposal recommends a future-ready Computer Science and Engineering curriculum for 2030, aligned with two target career pathways:

- Full-Stack Software Engineer
- AI/ML Engineer

The proposal builds on the published ICFAI Tech School Hyderabad B.Tech CSE programme structure and a comparison of three real employer job postings. It aims to strengthen practical engineering, applied AI, software quality, responsible AI, deployment, and industry-linked learning.

## 4. Redesign Principles

1. Preserve core computer science foundations.
2. Integrate AI-assisted development with verification and human accountability.
3. Strengthen full-stack engineering, testing, security, deployment, and maintainability.
4. Teach AI/ML through reproducible experiments and measurable evaluation.
5. Embed privacy, bias assessment, explainability, and responsible AI practices.
6. Connect course projects to a common end-to-end capstone.
7. Calculate all proposed credit changes against a verified programme-credit denominator.

## 8. Five Practical AI Exercises

### Exercise 1 - Data Structures

**Task:** Ask an AI coding assistant to suggest an implementation of a queue or hash table.

**Student work:** Independently verify correctness, write edge-case tests, compare time complexity, and document at least one issue in the generated solution.

**Assessment:** Correctness, complexity reasoning, tests, and ability to explain the code without AI assistance.

### Exercise 2 - Object-Oriented Programming

**Task:** Use AI to suggest a refactor of a small class-based application.

**Student work:** Evaluate whether the proposed design improves cohesion, coupling, readability, and adherence to object-oriented principles. Reject changes that introduce unnecessary complexity.

**Assessment:** Before-and-after design, unit tests, and a short design justification.

### Exercise 3 - Database Management Systems

**Task:** Use AI to draft a database schema and SQL queries for an expense-tracking application.

**Student work:** Check normalisation, primary and foreign keys, query correctness, parameterised queries, and role-based access. Test the queries against sample data.

**Assessment:** Schema, working queries, test cases, and security review.

### Exercise 4 - Web Enabled Technologies

**Task:** Build a small full-stack issue-tracking application with a React interface, REST API, and relational database.

**Student work:** Use AI selectively for scaffolding or debugging, but verify validation, authentication, error handling, accessibility, and API behaviour. Add automated tests and deploy a working version.

**Assessment:** Functionality, test results, security checks, deployment, and explanation of AI-assisted changes.

### Exercise 5 - Machine Learning

**Task:** Train and compare two baseline classification models using an appropriate public dataset.

**Student work:** Inspect data quality, create a reproducible train/test split, prevent data leakage, compare suitable metrics, examine errors, and discuss limitations and potential bias. AI may assist with code, but results must be independently reproduced.

**Assessment:** Reproducible notebook, metric comparison, error analysis, and responsible-use discussion.

## 9. Proposed Credit-Change Plan

The redesign should change 20-25% of the verified programme credits, as required by the assignment. The denominator must include only credits that count toward the applicable degree structure; elective catalogues must not be added as if every elective were compulsory.

Let:

- **T** = verified total programme credits.
- **R** = credits materially redesigned, replaced, or newly allocated under the proposal.

The target is:

**0.20T <= R <= 0.25T**

### Credit-accounting rules

1. Do not count an existing course as newly added merely because its teaching methods are updated.
2. Distinguish revised course content from changed credit allocation.
3. Count each credit only once.
4. Document which courses are retained, revised, merged, replaced, or newly proposed.
5. Report both the number of affected credits and the percentage of the verified total.
6. If the baseline cannot be verified, label the calculation provisional instead of presenting an unsupported percentage.

## 10. Shared Capstone Connecting Tasks 1 and 2

Propose a **Placement Support Workflow and Analytics Platform** as a capstone connecting the workflow prototype from Task 1 with the curriculum redesign.

Possible components:

- A full-stack request-management application with validation, duplicate warnings, status transitions, and an audit trail.
- A dashboard for synthetic request volumes, categories, resolution times, and escalation patterns.
- An optional ML extension that classifies request categories or flags potential duplicates.
- Automated tests for normal submissions, missing fields, duplicate requests, invalid status transitions, and unavailable services.
- A documented privacy and responsible-AI review.

The current Task 1 prototype is a local front-end demonstration with in-memory data. The capstone would be a future extension, not a claim that a production system or institutional integration already exists.

## 11. Risks and Mitigations

| Risk | Mitigation |
|---|---|
| Incorrect AI-generated code | Require tests, code review, and student explanation. |
| Data privacy exposure | Use synthetic or approved anonymised data; never upload confidential student records to public AI tools. |
| Bias or unreliable ML output | Evaluate errors across relevant groups when suitable data is available; document limitations. |
| Overdependence on AI | Include independent coding, viva questions, and closed-AI assessment components. |
| Curriculum overload | Integrate exercises into existing assessments and remove redundant work where appropriate. |
| Unsupported credit calculations | Verify the applicable batch structure and calculate affected credits transparently. |

## 12. Implementation and Evaluation

**Phase 1 - Validation:** Confirm the applicable CSE curriculum, official course credits, elective rules, and final-year requirements.

**Phase 2 - Pilot:** Introduce the five AI exercises in selected existing courses and evaluate student work using common rubrics.

**Phase 3 - Capstone integration:** Connect web engineering, database design, software testing, cloud deployment, and optional ML into a single project.

**Phase 4 - Review:** Measure test quality, project reliability, reproducibility, security practices, student understanding, and feedback from industry reviewers.

The proposal should be revised after the pilot using observed evidence rather than assuming that AI integration automatically improves learning outcomes.

## 13. Conclusion

The proposed 2030 CSE curriculum preserves core computer science knowledge while strengthening applied software engineering, AI/ML evaluation, deployment, testing, and responsible AI. The next validation step is to confirm the official credit structure for the target batch, then calculate and document the required 20-25% redesign using a transparent course-by-course change register.
